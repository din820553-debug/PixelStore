# Покупки и документы: один продавец

## Что готово

Python 3.12, Waitress 3.0.2 и встроенная SQLite. Один кабинет владельца, без регистрации других продавцов. Заказ сохраняет ник получателя, товары, количество и рублёвые цены на момент оформления. Изменение каталога не меняет историю. Для MVP++ требуется подтверждение наличия MVP+ у получателя; это заявление покупателя, а не проверка API Hypixel.

Оплата и выполнение имеют независимые статусы. Оплата, возврат и закупка отмечаются продавцом вручную с подтверждением операции. Эти действия не списывают и не возвращают деньги. Витрина пока создаёт демозаказы; форма «Внести покупку вручную» учитывает реальные покупки, принятые вне сайта, и создаёт их неоплаченными.

Фактические расходы вводятся раздельно: закупка, комиссия карты, приём платежа, вывод, налог/отчисление, другое. Остаток учитывает расходы и отмеченный возврат; это не налоговый регистр и не гарантия чистой прибыли. Заметки и расходы не видны покупателям. Журнал действий, поиск, фильтры, CSV и резервная копия доступны продавцу.

## Чеки и доступ

Хранятся уже выданные PDF/JPEG/PNG/WebP: до 5 МБ, до 20 документов на заказ. Система не выпускает фискальные чеки и не отправляет данные в ФНС. Скачанное описание заказа явно помечено «Не является фискальным чеком».

Файлы находятся внутри SQLite, а не в публичном каталоге. По умолчанию доступны только продавцу. Можно явно открыть покупателю конкретный документ и позже отозвать доступ. Уже скачанные копии это не удаляет. SHA-256 идентифицирует копию, но не доказывает подлинность документа. Загружайте только относящиеся к покупке файлы, без полных реквизитов карты.

Покупатель открывает заказ по случайному 256-битному ключу. Ключ хранится в истории браузера и скачанном описании, передаётся через Authorization, а не URL; сервер хранит хеш. В разделе «Мои заказы» можно перенести заказ на другое устройство по идентификатору и ключу. Публичного списка покупателей нет. Не публикуйте ключи.

## Что видно на скриншоте h1cloud

- Контейнер `ghcr.io/ptero-eggs/yolks:python_3.12`, память 512 МБ, диск 1 ГБ.
- Выделенный адрес приложения: `de-bots5.h1cloud.net:25011`.
- SFTP: `de-bots5.h1cloud.net`, порт **2022**. Это не подтверждение SSH-доступа.
- Запуск задаётся через `PY_FILE`, зависимости — через `PY_PACKAGES`.

Поэтому здесь не нужны Node.js, systemd, Docker или установка Nginx от root. Наличие HTTPS-прокси по скриншоту не подтверждено. Подготовленный код и архив сами по себе не означают установку на хостинг.

## Загрузка через панель / SFTP

1. Сохраните существующие файлы хостинга отдельно, если они нужны. Загрузите и распакуйте архив в корень приложения: `run.py`, `server/`, `requirements.txt`, `catalog.json`, файлы витрины и `assets/` должны оказаться рядом. При использовании SFTP можно распаковать архив на компьютере и загрузить содержимое.
2. В панели укажите **`PY_FILE=run.py`**, **`PY_PACKAGES=waitress==3.0.2`**. Приложение слушает `0.0.0.0` и порт `SERVER_PORT`/`PORT`, если его задаёт панель; иначе `25011`. Оно рассчитано на один процесс, использует два потока Waitress.
3. Создайте приватный каталог `data` и файл `data/settings.json`, скопировав структуру из `settings.example.json`. Не редактируйте публичный пример для хранения настоящего ключа. Через файловый менеджер/SFTP заполните:

```json
{
  "admin_token": "",
  "public_origin": "",
  "port": 25011,
  "max_data_mb": 300,
  "min_free_mb": 50
}
```

В `admin_token` вставьте случайный пароль из менеджера паролей длиной минимум 32 символа. Не отправляйте его в чат и не загружайте в GitHub. Без ключа вход отключён. `public_origin` оставьте пустым, пока хостинг не выдаст HTTPS-адрес; затем впишите только origin вида `https://orders.example.com`, без пути. Это пример адреса, не подключённый домен.

Переменные окружения `ADMIN_TOKEN`, `PUBLIC_ORIGIN`, `SERVER_PORT`/`PORT`, `MAX_DATA_MB`, `MIN_FREE_MB` имеют приоритет перед файлом. Если панель не позволяет добавлять переменные, используйте `data/settings.json`. Сервер не публикует этот файл; при чтении устанавливает права `0600`. `DATA_DIR` позволяет изменить каталог данных; тогда файл настроек ищется в нём. `.env.example` — только справка, `.env` автоматически не читается.

4. Нажмите запуск в панели. В консоли должна появиться строка `PixelStore Python` и порт, без ключа владельца. По адресу `/api/health` сервер возвращает `ok: true`, `paymentsConnected: false` и признак `publicApiReady`.
5. До настройки HTTPS публичный адрес предназначен только для проверки доступности. Витрина на публичном HTTP остаётся локальной демонстрацией, кабинет отключён в интерфейсе. Не вводите ключ владельца и не загружайте реальные документы через HTTP. Локальный режим `localhost` разрешён для разработки.

## HTTPS: следующий необходимый шаг

Нужно получить HTTPS-прокси/домен, ведущий к порту **25011**. Waitress сам не выдаёт TLS-сертификат. Пока в панели такая возможность не найдена, подготовлен текст для обращения в поддержку — отправляет владелец:

> У меня Python-приложение на выделенном порту 25011 сервера de-bots5.h1cloud.net. Можно ли подключить домен или выдать HTTPS-адрес с проксированием к этому порту? Нужны обычный HTTP API, загрузка запроса до 8 МБ и скачивание резервной копии. Если это не поддерживается текущим тарифом, какой тариф поддерживает?

Не подставляйте `http://de-bots5.h1cloud.net:25011` в GitHub Pages: HTTPS-страница не сможет штатно обращаться к HTTP API. Не используйте временную ссылку туннеля как постоянный адрес магазина. Если тариф не поддерживает HTTPS-прокси, выберите хостинг Python с HTTPS или полноценный VPS с таким прокси.

После получения HTTPS:

1. Настройте прокси и сертификат в хостинге, внесите точный HTTPS-origin в `data/settings.json` → `public_origin`, перезапустите приложение.
2. Откройте `https://ваш-домен/admin`, войдите, создайте тестовый заказ, проверьте документ, закрытие доступа, резервную копию и восстановление. На HTTPS cookie владельца получает Secure, HttpOnly и SameSite=Strict; сеанс — 12 часов. Перезапуск сервера завершает старые сеансы.
3. Можно использовать всю витрину с этого же домена. Для сохранения витрины на GitHub Pages укажите в публичном `api-config.js` только HTTPS-origin сервера и опубликуйте:

```js
window.PIXELSTORE_API_BASE = 'https://orders.example.com';
```

Здесь не должно быть ключей. Разрешённый origin GitHub уже настроен: `https://din820553-debug.github.io` (без `/PixelStore/`). При смене домена витрины задайте точные `ALLOWED_ORIGINS` через окружение, несколько через запятую; `*` не разрешён. Кабинет открывайте на домене сервера, не GitHub Pages.

4. Проверьте заказ именно с опубликованной витрины и его появление у продавца. При недоступном настроенном API сайт сообщает ошибку, не переключается молча на локальную историю. Реальная оплата по-прежнему не подключена.

## Диск 1 ГБ и резервирование

База с документами имеет исходный лимит **300 МБ**, минимальный запас свободного места — **50 МБ**. Оставшееся место требуется для WAL SQLite, временных файлов, резервной копии, кода, библиотек и журналов панели. Это консервативный стартовый лимит, не расчёт гарантированной вместимости тарифа. Загрузка большого файла требует дополнительного запаса; при нехватке места запись отклоняется. Кабинет показывает использование базы и предупреждение от 80% лимита. Не увеличивайте лимит до 1 ГБ на диске 1 ГБ.

- Кнопка **«Резервная копия базы»** скачивает согласованную SQLite-копию вместе с документами и удаляет временную копию на сервере. Экспорт CSV содержит учётные строки, не файлы документов.
- Для локального терминала: `python -m server.backup`; каталог назначения задаётся `BACKUP_DIR`, исходный — `DATA_DIR`. Команда не требует Node.js. Пункт SFTP не означает, что панель позволяет выполнять shell-команды.
- Делайте копию ежедневно и перед обновлениями, храните несколько версий на отдельном защищённом носителе. Автоматическое расписание пока не включено.
- Файл `data/settings.json` с ключом нужно сохранять отдельно в защищённом месте; он не входит в резервную копию SQLite. Копии базы содержат данные покупателей — не публикуйте их.
- Обновления: остановите приложение, сохраните копию, замените только код. **Не удаляйте и не заменяйте `data/` архивом новой версии.**
- Восстановление: остановите единственный процесс, сохраните исходную базу и её WAL/SHM отдельно; положите проверенную копию как `data/pixelstore.sqlite`, уберите только старые WAL/SHM из рабочего каталога после остановки и сохранения, запустите и проверьте заказы/документы.
- Не копируйте только работающий `.sqlite` без WAL и не удаляйте WAL на ходу. Используйте кнопку копии или команду резервирования.

## Локальная проверка и каталог

Python 3.12:

```sh
pip install -r requirements.txt
python -m unittest discover -s test -v
python run.py
```

Витрина: http://localhost:25011; кабинет: http://localhost:25011/admin. Для входа нужен ключ через настройки/окружение. Каталог редактируется в `catalog.json`, затем `python scripts/build_catalog.py` обновляет статический `catalog.js`. Сервер рассчитывает суммы сам, отклоняет устаревшую цену, требует подтверждение MVP+ для MVP++. Идентичный повтор запроса возвращает прежний заказ даже после изменения цены.

## Что добавить после установки

1. Проверенное расписание резервирования и контроль диска/ошибок.
2. После согласования модели продаж — серверную интеграцию выбранной кассы со сверкой уведомлений, суммы, валюты, заказа и защитой от повторов. Страница успеха не подтверждает оплату.
3. Нужный способ выпуска фискальных чеков и связь с возвратами — после выбора налогового оформления.

Антивирусная проверка загружаемых файлов, автоматическое удаление по срокам и автоматическая выдача товаров пока не реализованы. Документы скачиваются вложением, их тип и размер проверяются. Сроки хранения задаёт владелец; автоматическое удаление выключено, чтобы не потерять подтверждения без согласованной политики.
